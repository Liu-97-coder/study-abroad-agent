# 一步步把这个项目做出来

这份文档讲施工顺序，不是功能清单。原语雀文档给的是 6.5 个月的团队排期；一个人自学、边做边理解，按下面 16 个 Step 走，大约 4 到 6 周可以做到能讲清楚、能跑通、能改得动。

每个 Step 分四块：目标、动手、验收、坑。验收不过就不要往下走，AI 项目最容易死在"看起来能跑"。

## Step 0 · 把骨架立起来

**动手**

```

建目录（已建好，理解即可）：

```

**验收**

```powershell

```

**坑**

## Step 1 · 先定契约：CustomerState

**目标**：让七个 Agent 说同一种话。**先定状态，再写 Agent**，这是本项目最重要的一条经验。

**动手**：看 `schema/state_schema.py`，把 `agent_outputs` 当成唯一事实来源。

```python
class CustomerState(BaseModel):
    customer_id: str
    trace_id: str = ""
    stage: str = "clue"                       # clue→consult→signed→material→document→application→offer→visa→finished
    student_info: dict = {}
    agent_outputs: dict = {}                  # 每个 Agent 的产出都写这里
    risk_tags: list[str] = []
    task_list: list[dict] = []
    history: list[str] = []
    errors: list[str] = []
```

同时把 8 个业务结构体也定了（`schema/student_schema.py`、`school_schema.py`…）。
**为什么先定结构体**：字段定不下来，Prompt 就会反复改；Prompt 反复改，测试就永远红。

**验收**

```powershell
.\.venv\Scripts\python.exe -c "from ai_agent_core.schema import CustomerState, SchoolItem; print(CustomerState(customer_id='x').model_dump().keys())"
```

**坑**

- `list[str] = []` 在 Pydantic 里是安全的（会拷贝），但在普通 dataclass 里是共享可变默认值——本项目数据结构统一用 Pydantic。
- **状态字段要给默认值**，否则二期加字段时会逼你改所有调用方（这是"插件式扩展"的前提，见 11 篇亮点 9）。

## Step 2 · 先有可观测性：Trace

**目标**：任何一个客户的任何一步，都能查到"谁调的、花了多久、输入输出是什么"。

**动手**：`base/logger_trace.py`

- `new_trace_id()` 生成 `tr-xxxxxxxx`
- `event(agent, event, level, trace_id, customer_id, **payload)` 落 JSONL
- 内存里留 3000 条环形缓冲，支持 `query(customer_id=...)`

**验收**

跑完下面的 Step 9 后：

```powershell
.\.venv\Scripts\python.exe -c "from ai_agent_core.base.context import get_context; ctx=get_context(); print(ctx.logger.stats()); print(ctx.logger.query(customer_id='demo-001', limit=3))"
```

**坑**

- 日志里**不要塞完整 Prompt**：字符数会爆。本项目只记 `prompt_preview` 120 字 + 耗时 + 模型名。
- `trace_id` 必须在 Agent 入口处补全，否则并行风控拿不到同一个 ID。

## Step 3 · LLM 统一调度池（先做 mock，非常关键）

**目标**：所有 Agent 只通过 `ctx.llm` 拿结果，**永不直接调 HTTP**。

**动手**：`base/llm_dispatch.py`

四个能力，缺一不可：

1. **分层**：`tier="big"` 写文书/评估，`tier="small"` 做抽取/纪要/检测
2. **缓存**：`sha1(model+prompt)` → TTL 1h（同类文书反复生成不重复花钱）
3. **限流**：单客户同时最多 2 个调用（`Semaphore`）
4. **兜底**：超时重试 2 次，失败返回调用方给的 `fallback`，**绝不抛异常**

```python
def text(self, prompt, fallback="", tier="big", customer_id="system"): ...
def json(self, prompt, fallback=None, tier="big", customer_id="system"): ...
```

**为什么 mock 模式不是偷懒**：mock 模式强制你先写"规则兜底"。
一个 Agent 如果连规则都产不出可用结果，接了大模型也只是把错误包得更漂亮。
本项目全部 Agent 都遵守「**数字走规则，文字走模型**」。

**验收**

```powershell
.\.venv\Scripts\python.exe -c "from ai_agent_core.base.context import get_context; c=get_context(); print(c.llm.available, c.llm.text('hi','fallback文本'))"
```

**坑**

- `LLM_PROVIDER=mock` 时 `available=False`，所有调用直接返回 fallback —— 这是设计，不是 bug。
- 响应格式不统一（有的模型不支持 `response_format`）：代码里 400 时会去掉该参数重试一次。

## Step 4 · RAG：四个库 + 三段检索

**目标**：院校/签证/文书/内控四类知识物理隔离，检索结果**必带来源**。

**动手**：`base/rag_client.py` + `base/embeddings.py`

1. **四库隔离**：`COLLECTIONS = {school, visa, writing, compliance}`，一个库一个 JSON（或 Milvus Collection）
2. **入库**：`ingest(collection, docs)`，每条必须有 `source_id`
3. **分片**：`split_text(size=520, overlap=100)`，按句号/换行切，**别把一句话切断**
4. **三段检索**：

```python
where = {"country": {"$in": ["英国"]}, "gpa_min": {"$lte": 3.2}}   # ① 标量前置过滤
scored = cosine(query_vec, record.vector)                          # ② 向量召回 Top20
final = 0.75*vec + 0.25*关键词重叠                                  # ③ 重排序（有真实 LLM 可换 LLM 打分）
```

5. **溯源**：`RetrievedChunk.source_info` 里放 `source_id / source_name / update_time`，一路传到前端

**验收**

```powershell
.\.venv\Scripts\python.exe scripts\ingest_seed.py
.\.venv\Scripts\python.exe scripts\check_rag.py --collection school --query "英国 计算机硕士 GPA" --country 英国 --top 3
```

要能看到 `source=school-0004` 这种 ID，以及"喂给 LLM 的上下文预览"里每段都带来源。

**坑**

- **分片函数最容易写出死循环**：文末若 `end == len(text)` 不 break，`start = end - overlap` 会原地打转，产出上百个 99 字碎片。本项目已修（`if end >= len(text): break`）。
- 分片太碎（<100 字）会让模型丢上下文；太大（>800 字）会稀释检索精度。政策类 500 左右、模板类 300 左右比较稳。
- CSV 里 **`£38,500` 这种带逗号的金额会把列冲散**，入库前必须清洗（本项目种子数据用 `£38500`）。

## Step 5 · 灌种子数据（先让库里有东西）

**目标**：26 条院校 + 签证政策 + 文书素材 + 合规词库。

**动手**：`scripts/ingest_seed.py`

- CSV → 结构化字段进 `metadata`（`gpa_min`、`ielts_min`、`country`…），正文给 embedding
- Markdown → `ingest_file()` 自动分片，`source_id = visa:visa_policies#3`
- JSON → 话术模板、退费规则、违规词逐条入库

**验收**

```powershell
.\.venv\Scripts\python.exe scripts\check_rag.py --stats
# {'school': 26, 'visa': 4, 'writing': 4, 'compliance': 11}
```

**坑**

- `metadata` 里的数值类型要转 `float/int`，否则 `$lte` 过滤会因字符串比较失效。
- 重灌时先 `delete_document(prefix)`，否则旧分片残留（本项目 `ingest_file` 已内置）。

## Step 6 · OCR：文件 → 结构化实体

**目标**：成绩单/存款证明/Offer/护照，都能抽出"均分、余额、存期、条件、护照号"。
**而且手机拍的照片也要能认**（这是学生端能用起来的前提）。

**动手**：`base/ocr_client.py`

1. `read_text()`：txt/md 直读，pdf 走 `pypdf`，图片走 OCR
2. 图片 OCR 三个后端：
   - `rapidocr`（**推荐**）：`pip install rapidocr-onnxruntime pillow`，ONNX 推理，Windows 免编译
   - `paddleocr`：文档原始方案，体积大、适合有 GPU 的机器
   - `stub`：只吃文本；但如果装了 rapidocr，上传图片会自动走它
3. 预处理：EXIF 旋转矫正 + 宽度 <900 自动放大 2 倍（手机拍照识别率的关键）
4. `classify()`：关键词打分分七类
5. `extract_entities()`：正则抽 `gpa / average_score / ielts / fund_amount / deposit_days / passport_no / deadline / major`
6. `mask()`：护照号、身份证、银行卡打码
7. `parse()`：返回 `ExtractedDoc`，带 `confidence` 与 `warnings`

**验收**

```powershell
.\.venv\Scripts\python.exe scripts\ocr_demo.py
```

真实输出（生成样例图 + 识别）：

```
=== sample_deposit.png ===
文件类型：存款证明  置信度：1.0
  fund_amount: 400000.0   deposit_date: 2026-06-01   deposit_days: 180
=== sample_transcript.png ===
  gpa: 3.6   average_score: 88.0   major: 计算机科学与技术   school_name: 南京理工大学
```

**坑**

- 金额单位：`30万` vs `300000` 要统一到元，否则资金校验全错。
- 存期：`存期 30 天` 和 `存入日期 2026-10-20` 是两条不同来源，**取不到就标"存期未知"，不要猜**。
- 中文紧贴证件号（`护照号E12345678`）时 `\b` 不成立，脱敏要用前后断言 `(?<![A-Za-z0-9])`。
- OCR 会把两行粘一起（`姓名：李同学专业：计算机`），姓名要用后向断言截断，否则抽出"李同学专"。

## Step 7 · 安全护栏：三层拦截

**目标**：任何要发给客户的话，先过这道闸。

**动手**：`base/safety_middleware.py`

| 层 | 做法 | 解决什么 |
| --- | --- | --- |
| 1 关键词 | 违规词库正则扫描 | 毫秒级兜底，绝不漏"保录" |
| 2 语境 | 看词前后 14 字：有"不做/禁止/无法"→低；有"能不能/假设/吗"→中；否则高 | 误报（"我们不做保录"被判违规） |
| 3 语义 | 配了真实 LLM 再复核一次 | 客服玩笑 vs 正式承诺 |
| 4 溯源 | `verify_citations(items)` 检查每条硬数据有没有 `source_id` | 幻觉分数/截止日期 |

**验收**

```powershell
.\.venv\Scripts\python.exe -c "from ai_agent_core.base.context import get_context; s=get_context().safety; print(s.check('我们保录前50').level, s.check('我们不做保录').level, s.check('能不能保录?').level)"
# 期望：high  low  medium
```

**坑**

- 只做关键词，误报会高到顾问直接关掉功能；只做 LLM，延迟和成本扛不住。**必须两层串联**。
- 拦截后的文本要**替换**而不是删除（`NOTICE_TEXT`），否则前端拿到空字符串会以为生成失败。

## Step 8 · BaseAgent + LangGraph：把 Agent 变成节点

**目标**：新增一个 Agent 只写一个目录 + 注册一行。

**动手**

1. `base/base_agent.py`：`run()` 负责 trace、异常兜底、存中台；子类只写 `_run()`
2. `base/graph_engine.py`：

```python
STAGE_AGENT = {"clue": "school_agent", "signed": "material_agent", ...}
PIPELINE    = {"school_agent": "signed", "material_agent": "document", ...}  # 仅 auto_advance 用
```

3. 路由函数 `next_agent(state)` 只回答一个问题：**下一步该谁跑，或者结束**
4. 风控 Agent 作为"并行钩子"：每个业务 Agent 跑完就调一次（只读、幂等、不阻塞）
5. `build_agents(ctx)` 注册表

**验收**

```powershell
.\.venv\Scripts\python.exe scripts\smoke_test.py
# 执行链：school_agent → risk_agent → material_agent → document_agent → application_agent → offer_agent → visa_agent
```

**坑**

- **`StudentState` 被整体覆盖是最常见事故**：`state.student_info = student.model_dump()` 会把 `uploaded_files`、`emails` 全冲掉，下游 Agent 拿到的全是空。正确写法是合并：`{**state.student_info, **new}`。
- LangGraph 的节点返回值要与 State 类型对齐；本项目用"返回完整 dict"最稳，避免增量合并歧义。
- 演示用 `auto_advance=True` 会自动推进阶段；**生产必须人工确认**，否则 AI 会替顾问做决定。

## Step 9 · 一期 A：选校 Agent（6 个子步骤）

**目标**：一段聊天 → 学生档案 → 三档清单 → 评估报告 → 合规话术 → 咨询纪要。

| 子步骤 | 文件 | 关键点 |
| --- | --- | --- |
| 1 抽取 | `student_extract.py` | 规则正则 + LLM 补漏；GPA 统一 4.0 制；缺字段生成追问话术 |
| 2 筛选 | `school_filter.py` | 标量过滤（国家/学位）+ 硬门槛（GPA 差 >0.5 剔除、已截止剔除） |
| 3 分层 | `school_score.py` | 难度指数 = 60% 项目难度 + 15% GPA 差距 + 10% 语言 + 5% 背景 + 10% 截止 |
| 4 报告 | `report_generator.py` | 规则算事实（硬件/优势/短板/窗口/评级），LLM 只写文案 |
| 5 话术 | `talk_generator.py` | 意图识别 → 内控库取模板 → 过护栏 |
| 6 纪要 | `chat_summary.py` | 七段式；待办自动同步 |

**为什么要"项目难度"占 60%**：只按"学生差多少"打分，3.2 的学生看什么都像保底；
只看 QS 又忽略个体差异。两者加权，顾问才能看到"这校本身难 + 我差 0.3"这种可核对理由。
（详见 `docs/架构决策.md` 决策 2）

**验收**

```powershell
.\.venv\Scripts\python.exe scripts\smoke_test.py
# 冲刺 4 所 / 匹配 5 所 / 保底 8 所，每条带 source_id
```

**坑**

- 分数如果全挤在"匹配"，先检查是不是某一维权重过大（本项目调过两版才拉开梯度）。
- **保底档为空不是 bug，是业务信号**：要在报告里明说"建议扩大国家范围"，而不是硬凑一所。
- 话术意图判断有优先级："能不能保录前 50" 同时命中"名校执念"和"保录询问"，**必须先判保录**。

## Step 10 · 一期 B：文书 Agent（6 个子步骤）

| 4 推荐信 | `ref_generator.py` | 学术/企业两风格 × 2 版 |
| 5 质检 | `doc_quality_check.py` | 六维：真实/专业/模板化/空话/逻辑/语法 |
| 6 版本 | `doc_version_mgr.py` | 每次生成一个 `version_id`，状态 待修改→已审核→最终版 |

**验收**

```powershell
.\.venv\Scripts\python.exe scripts\smoke_test.py
# 经历条目 4 条；质检 69.5；版本存档 PS/CV/推荐信/原始素材
```

**坑**

- PS 最容易被写成"通用模板"。硬约束是：**每个段落必须绑定一条真实经历**，没有素材的段落留空待补，不许编。
- 质检的"模板化程度"要**反向计分**（越高越差），否则总分会被算反。
- 版本管理不只是存档：它是**合同边界**（改几版算超范围）和**纠纷举证**（哪句是 AI 写的）。

## Step 11 · 二期：材料 / 网申 / Offer / 签证

四个 Agent 的开发套路完全一致：**先生成清单/主体，再逐项校验，最后产出待办**。

| Agent | 主流程 | 最容易做错的点 |
| --- | --- | --- |
| 材料 | 清单（按国家/学位/在读状态分支）→ OCR 校验 → 缺失比对 → 分级待办 | 在校生不该出现"毕业证"；催收要分初次/逾期3天/逾期7天 |
| 网申 | 表单交叉比对 → 邮件意图五分类 → 30/15/7 三级预警 → 推荐人 7 天跟进 | 姓名拼音/护照号必须与 OCR 数据比对，不能只做格式校验 |
| Offer | OCR 抽条件 → 院校政策匹配 → 达标风险测算 → CAS 倒推时间线 | Offer 上的截止与官网不一致时，**要标"政策冲突"而不是覆盖** |
| 签证 | 材料包（含出资类型分支）→ 资金四维风险 → 时间线 → 缺失催收 | 英国 28 天存期 / 澳洲 6 个月；单笔 40% 以上且 30 天内 = 大额临存 |

**验收**：`smoke_test.py` 里对应输出——

```
【3】材料 Agent 清单 13 项，缺失 …
【4】网申 Agent 表单错误：['护照号', 'GPA'] 邮件意图：['补件通知', '面试邀请']
【5】Offer Agent 均分 85% → 中（差 3.0 分）；IELTS 7.0 → 中（差 0.5 分）
【6】签证 Agent 金额不足 / 存期不足 / 大额临存 / 流水断档
```

**坑**

- 金额单位混用（英镑/人民币）是资金校验的头号 bug，本项目统一按人民币口径比对并在注释声明。
- 时间线必须**倒推**：从入境日往前扣体检、公证、出签周期，而不是从今天往后加。
- `re` 模式里没有捕获组却调 `m.group(1)` 会抛 `IndexError: no such group`——本项目 Offer 的"毕业证"规则就踩过。

## Step 12 · 三期：合规 / 预判 / 交接

| 模块 | 做法 | 关键点 |

## Step 14 · 端到端验收（12 条断言）

`scripts/smoke_test.py` 最后那段 `checks` 就是验收清单：

1. 选校有产出
2. 三档至少两档非空
3. **每条选校结果都带 source_id**（防幻觉）
4. 文书有质检分
5. 文书版本已存档
6. 材料清单已生成
7. 网申护照号错误被拦截
8. Offer 条件被解析（≥2 条）
9. 签证资金风险被识别
10. 违规话术被拦截
11. 产生了待办
12. 全链路无异常

全绿才算一期到三期打通。

**怎么用它做回归**：改任何 Agent 后重跑；哪条红就去看那一条对应的输出段，
比在 3000 行日志里翻要快得多。

## Step 15 · 上线前要补的三件事

1. **灰度**：先给 2-3 个顾问用，重点看"AI 建议被采纳率"和"采纳后被推翻率"。
2. **成本**：小模型做抽取/纪要，大模型只写文书与评估；缓存命中率要做到 30% 以上。
3. **数据**：知识库是系统的天花板。院校线、签证政策过期，AI 越"聪明"错得越快 —— 必须配运营专员 + 增量同步。

## Step 16 · 加一个 Agent（用"面试模拟"演练插件式扩展）

**目标**：只碰 3 处，就把第八个 Agent 加进系统，主流程一行不改。

**动手**（真实代码已经在仓库里，对照看）：

1. **新建目录** `ai_agent_core/phase2/interview_agent/`
   - `question_bank.py`：题库 JSON + RAG 检索 + **题型梯度**（只按相似度取前 6 题会抽出 3 道学术题）
   - `answer_scorer.py`：五维规则打分（结构/具体性/量化/专业匹配/表达）
   - `interview_agent_node.py`：`class InterviewAgent(BaseAgent)`，只写 `_run()`
2. **注册表加一行**：`base/graph_engine.py` 的 `build_agents()`
3. **路由加一个条件**：`next_agent()` 开头
   ```python
   if (state.student_info.get("interview_requested")
           and state.stage in {"application", "offer"}
           and "interview" not in state.agent_outputs):
       return "interview_agent"
   ```

再加 3 个东西才算完整（这就是"Agent 之外的交付物"）：
结构体 `schema/interview_schema.py`、接口 `api/interview_api.py`、前端 Tab。

**验收**

```powershell
.\.venv\Scripts\python.exe scripts\check_interview.py
# ① 生成 6 道题  题型有梯度：动机/学术/实习/行为/思辨/院校
# ② 好答案 75.7 分，敷衍答案 32.8 分
# ③ 报告含平均分与改进项
# ④ 执行链包含 interview_agent（被标记时才插入）
```

**坑**

- **只按检索相似度出题**会得到同质题目（实测 3 道学术题），必须单独做题型配平。
- 评分维度里"量化"最容易拿满分也最容易 25 分，学生练两遍就能感知差距 —— 这比"多练练"有用。
- 新 Agent 不要写进 `STAGE_AGENT` 主流程，否则每个客户都会被迫跑一次面试。

## 附录 A · 常见报错对照

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `ModuleNotFoundError: ai_agent_core.phase3.base` | 相对导入层级写错（`..` 应为 `...`） | 从包根往下数 `..` 的层数 |
| `IndexError: no such group` | 正则没有捕获组却 `m.group(1)` | 给模式加 `(...)` |
| CSV 字段错位 | 值里含逗号（`£38,500`） | 去掉千分位或加引号 |
| 三档全是"匹配" | 打分权重失衡 | 调 `phase1/school_agent/school_score.py` 的公式 |
| 下游 Agent 拿不到上传文件 | `student_info` 被整体覆盖 | 改成合并赋值 |
| 检索命中大量 99 字碎片 | 分片函数文末死循环 | `if end >= len(text): break` |
| 接口中文乱码 | 客户端未按 UTF-8 解码 | 用 `scripts/api_smoke.py` |
