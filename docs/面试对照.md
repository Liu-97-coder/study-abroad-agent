## 1. 线索 → 签证端到端 Agent 流水线

**一句话**：七个 Agent 挂在一条状态机上，靠客户阶段自动路由，而不是七个脚本串行调用。

- 代码：`base/graph_engine.py`（`STAGE_AGENT` / `next_agent` / `PIPELINE`）、`schema/state_schema.py`
- 可讲的细节：
  - 路由只回答"下一步谁跑或结束"，判断依据是 `agent_outputs` 里有没有对应产物，天然幂等。
  - 装了 LangGraph 走 `StateGraph`，没装自动退回等价的 `while` 循环 —— 两条路径调用同一批节点函数。
  - 阶段推进与"人工确认"分离：演示用 `auto_advance`，生产必须顾问点确认（写进调度层而不是靠约定）。
- 追问："流程中断了怎么续跑？" → 状态全部落 SQLite（`storage.save_customer`），下次 `load_state` 直接接着跑。

## 2. RAG 混合检索杜绝幻觉

**一句话**：三层检索（标量过滤 → 向量召回 → 重排）+ 强制 `source_id` 溯源。

- 代码：`base/rag_client.py`（`search` / `_match_meta` / `format_context`）、`base/safety_middleware.py:verify_citations`
- 可讲的细节：
  - 标量过滤把"国家/学位/GPA 下限/有效期"先筛一遍，候选集小一个数量级，既准又快。
  - 重排用"向量分 0.75 + 关键词重叠 0.25"，接真实模型可换 LLM 打分（`_llm_rerank`）。
  - 空结果不返回空数组，返回标准提示"知识库未命中，禁止编造"——这是防幻觉的最后一道。
  - 出库的每条都带 `source_info{source_id, source_name, update_time}`，一路传到前端。
- 追问："怎么保证不召回过期政策？" → 每条带 `valid_year` + `is_valid`，检索默认只取有效数据；增量更新走"删旧片→写新版"。

## 3. 多类型文档 OCR + 行业实体抽取

**一句话**：通用 OCR 只给文本，我们给的是"均分、存期、Con 条件、护照号"这类业务实体。

- 代码：`base/ocr_client.py`、`phase2/offer_agent/offer_ocr_parser.py`
- 可讲的细节：
  - 文件分类靠关键词打分（成绩单/存款证明/Offer/护照/在读/毕业/语言），七类。
  - 实体抽取是正则规则 + 单位归一（30 万 → 300000）+ 缺字段的 `warnings`，**抽不到就标缺失，绝不猜**。
  - Offer 是长英文法律句，正则先抓结构，LLM 再补长句理解，两边冲突标风险。
  - 敏感字段（护照号/身份证/银行卡）在 `mask()` 里打码，脱敏后的文本才进日志。
- 追问："模糊/倾斜图片怎么办？" → `OCR_BACKEND=paddleocr` 走真实识别 + 预处理；本项目默认吃文本，接口一致。

## 4. 选校智能分层打分模型

**一句话**：不是黑盒打分，是"项目难度 60% + 学生差距 40%"的可解释指数，每个维度都能给顾问看。

- 代码：`phase1/school_agent/school_score.py`（`score_one` 输出 `score_detail`）
- 可讲的细节：
  - 第一版只按"学生差多少"，结果 3.2 的学生看什么都是保底；第二版只按 QS，又变成敢冲 NUS。最终两段加权才拉开梯度。
  - 硬门槛拦截在 `school_filter.py`：GPA 差 0.5 以上直接剔除、已截止直接剔除，剔除原因回传给前端。
  - 风险标签是规则生成的（GPA差0.3 / 雅思差0.5 / 仅剩60天 / 竞争极大），不是模型自由发挥。
- 追问："分数怎么校准？" → 用真实案例回测：拿 20 个历史学生的最终录取结果，看三档命中率，再调权重。

## 5. 文书 Agent 不写模板套话

**一句话**：用"真实经历绑定 + 六维质检"把模板化文书挡在交付前。

- 代码：`phase1/doc_agent/ps_generator.py`、`doc_quality_check.py`
- 可讲的细节：
  - PS 固定六段逻辑链（启蒙→课程→科研→实习→院校匹配→规划），"院校匹配"段必须引用 RAG 里的课程素材。
  - 没有素材的段落留空并标"需顾问补充"，**不允许模型编经历**。
  - 质检六维里"模板化程度""空话冗余度"是反向计分（越高越差），总分 60 以下直接打高危标签、禁止交付。
  - 每版文书一个 `version_id`，状态 待修改→已审核→最终版，同时是"改几版算超范围"的合同依据。
- 追问："怎么判断模板化？" → 目前用通用句式命中率 + 空话词密度；更好的做法是训练一个分类器，或用 embedding 与模板库算相似度。

## 6. Conditional Offer 自动解析 & 达标风险

**一句话**：把长英文 Offer 拆成结构化条件，再算出"差几分、来不来得及"。

- 代码：`phase2/offer_agent/offer_ocr_parser.py`、`cond_risk_calculator.py`、`offer_policy_matcher.py`
- 可讲的细节：
  - 条件分四类（均分/语言/GRE/毕业证），每条给"要求值 → 学生当前值 → 差距 → 风险等级 → 整改建议"。
  - 均分差 3 分以内判"中风险"（剩余课程能补），超过判"高风险"（建议加申保底）。
  - Offer 上的截止与官网 RAG 记录不一致时不覆盖，而是标"政策冲突，以官网为准并留痕"。
  - 押金规则单独判"可退/不可退"，不可退直接打高危 —— 这是退费纠纷的高发点。
- 追问："无条件 Offer 怎么处理？" → `is_conditional` 判定为 False 时跳过条件测算，直接进 CAS 时间线。

## 7. 签证资金 AI 风险推理

**一句话**：四个维度（余额/存期/大额临存/流水断档）把"拒签风险"说成人话。

- 代码：`phase2/visa_agent/fund_risk_analyzer.py`
- 可讲的细节：
  - 存期按国家差异化：英国 28 天、澳洲 180 天、加拿大 120 天；缺数据标"存期未知"而不是默认达标。
  - 大额临存规则：单笔 ≥ 总额 40% 且发生在 30 天内 → 高风险，给"补资金来源证明/延长存期"两条整改路径。
  - 每条风险都配 `fix_plan`，顾问可以原样转给客户，不用二次翻译。
  - 判定逻辑全在规则里，LLM 只补充话术，**不改结论**——签证判定错一次就是拒签。
- 追问："各国规则每年变怎么办？" → 规则阈值集中在模块常量 + 签证 RAG 库，运营更新库、研发更新常量，两者都要留版本。

## 8. 并行常驻风控，实时合规拦截

**一句话**：关键词粗筛 + 语境判断 + LLM 语义复核，解决"误报太高没法用"。

- 代码：`base/safety_middleware.py`、`phase3/risk_agent/compliance_audit.py`
- 可讲的细节：
  - 只做关键词，"我们不做保录"会被误判；所以看词前后 14 字：出现"不做/禁止/无法"判低风险，出现"能不能/假设/吗"判中风险，其余判高危。
  - 高危直接替换成 `NOTICE_TEXT` 合规提示并落风险标签，而不是返回空。
  - 风控 Agent 是并行钩子（只读、幂等、异常吞掉），不会拖垮主流程。
- 追问："实时性怎么保证？" → 现在是步级（每跑完一个 Agent 扫一次）；真实时要用消息队列 + 流式检测，`scan_batch` 已预留批量入口。

## 9. 统一底座，Agent 插件式扩展

**一句话**：新增一个 Agent = 新建目录 + 继承 `BaseAgent` + 注册表加一行。

- 代码：`base/base_agent.py`、`base/graph_engine.py:build_agents`、`schema/state_schema.py`
- 可讲的细节：
  - 基类统一处理 trace、异常兜底、存中台、风险标签、待办，子类只写 `_run()`。
  - 状态结构体全部给默认值，二期/三期只往 `agent_outputs` / `risk_tags` 加 key，不改结构。
  - 这里踩过最大的坑：选校 Agent 里 `state.student_info = student.model_dump()` 把上传文件、邮件全冲掉，下游全空。改成合并赋值才通。
- 追问："怎么保证二期不改一期代码？" → 接口是 `run(state) -> state`，新增 Agent 只碰注册表和自己的目录；共享数据走 `agent_outputs` 的命名空间。

## 10. AI 输出留痕、可溯源、权责清晰

**一句话**：一次客户流程一个 `trace_id`，一版文书一个 `version_id`，一条数据一个 `source_id`。

- 代码：`base/logger_trace.py`、`storage.py`（`doc_versions` / `traces`）、`phase3/risk_agent/handover.py`
- 可讲的细节：
  - 日志落 JSONL（`ts/level/agent/event/trace_id/customer_id/payload`），内存留 3000 条供接口查询。
  - 日志里不存完整 Prompt（字符数爆炸），只存预览 + 模型 + 耗时 + 缓存命中。
  - 交接包按"紧急/风险/普通/待签约"四类打包，附文书版本与来源，新人能追到每一版是谁生成的。
  - 出现客诉时能回答："这句话是 AI 第 3 版生成的，顾问在第 4 版改成了这样"。
- 追问："存储成本怎么控？" → 日志分级 + 摘要化；文书只存版本差异与定稿；AI 原始输出按客户归档，结案 N 天后冷存储。
