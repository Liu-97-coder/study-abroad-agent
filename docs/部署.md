# 部署手册

> 三种方式按场景选：
>
> | 方式 | 适合 | 一条命令 | 本机验证状态 |
> | --- | --- | --- | --- |
> | A. 直跑（venv） | 开发、演示、自己电脑 | `scripts\dev.ps1` | ✅ 已跑通 |
> | B. Docker | 交付给别人、内网试用 | `scripts\docker-up.ps1` | ⚠️ 未实跑（本机无 Docker），依赖已做等价验证 |
> | C. Linux + systemd + nginx | 正式上线 | 见下文 unit 文件 | ⚠️ 未实跑（无服务器） |

---

## A. 本机直跑（最常用）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1     # 一次性
powershell -ExecutionPolicy Bypass -File scripts\dev.ps1       # 每次启动
```

数据都在 `runtime\`（`crm.db` + `rag\` + `uploads\`），关窗口不丢。

## B. Docker（推荐交付给别人）

### B.0 三步走（安装包已经下好了）

安装包已在 `C:\Users\25045\Downloads\DockerDesktopInstaller.exe`（约 600MB，官方签名）。

1. 双击项目里的 **`安装Docker.bat`** → 弹 UAC 点「是」→ 静默安装 3-8 分钟
   （脚本会顺带检查 WSL2；缺 WSL 会执行 `wsl --install --no-distribution`）
2. **重启电脑**（WSL2 内核要生效，这步跳不过去）
3. 开始菜单启动 Docker Desktop，等左下角显示 `Engine running`
   → 双击 **`启动Docker.bat`**，它会构建镜像、等健康检查、打印地址

> 没联网/下载失败？重下：
> <https://desktop.docker.com/win/main/amd64/Docker%20Desktop%20Installer.exe>
> 或用 winget：`winget install -e --id Docker.DockerDesktop`

### B.1 装 Docker Desktop（手动版）

1. 下载上述安装包 → 双击 → 安装时勾选 **Use WSL 2 instead of Hyper-V**
2. 如果提示 WSL 未安装，管理员 PowerShell 执行：
   ```powershell
   wsl --install --no-distribution
   ```
   **然后重启电脑**（这一步必须，否则 Docker 起不来）
3. 装完后启动 Docker Desktop，等左下角出现 `Engine running`
4. 验证：
   ```powershell
   docker version
   docker compose version
   ```

### B.2 起服务

```powershell
cd study-abroad-agent
Copy-Item .env.example .env                 # 改 AUTH_SECRET（生产必改）
powershell -ExecutionPolicy Bypass -File scripts\docker-up.ps1
```

脚本会：检查 Docker → 没启动就帮你拉起 → `docker compose up -d --build` → 等健康检查通过 → 打印地址。

手动等价命令：

```powershell
docker compose up -d --build
docker compose ps
docker compose logs -f agent
```

**预期输出**：

```
NAME                   IMAGE                       STATUS
study-abroad-agent     study-abroad-agent:1.1      Up 40 seconds (healthy)
```

打开 <http://127.0.0.1:8000/>，用 `admin/admin123` 登录。

### B.3 数据在哪

| 容器内 | 宿主机 | 内容 |
| --- | --- | --- |
| `/app/runtime` | `./runtime` | `crm.db`（客户/待办/风险/文书版本/面试场次）、`rag/`、`uploads/` |
| `/app/logs` | `./logs` | `trace-*.jsonl` |

所以**改镜像、重启容器都不会丢数据**；`docker compose down` 也不会（`-v` 才会删卷，这里没用卷）。

### B.4 常用命令

```powershell
docker compose ps                     # 状态（看 healthy）
docker compose logs -f agent          # 实时日志
docker compose restart agent          # 重启
docker compose down                   # 停止并删除容器（数据保留）
docker compose up -d --build          # 改代码后重建
```

### B.5 镜像里做了什么（`Dockerfile`）

1. `python:3.12-slim` + `pip install -r requirements.txt`
2. 非 root 用户 `appuser` 运行
3. `HEALTHCHECK` 调 `scripts/healthcheck.py`（Python 实现，镜像里不用装 curl）
4. 启动时先 `python scripts/ingest_seed.py`（幂等）再 `uvicorn --host 0.0.0.0`

### B.6 为什么"没实跑也敢交付"

本机没有 Docker（也没有 WSL 发行版），所以用**两层等价验证**代替：

```powershell
# 第一层：干净 venv 只装 requirements.txt，证明镜像的依赖层完整
.\.venv\Scripts\python.exe scripts\check_deploy.py

# 第二层：按容器的 CMD 原样启动，验证 0.0.0.0 绑定、健康检查、局域网可达
.\.venv\Scripts\python.exe scripts\check_prod.py
```

`check_prod.py` 实测输出：

```
① 按容器 CMD 的方式启动（0.0.0.0:8060）
  PASS  服务启动（0.0.0.0 绑定）
  PASS  本机 127.0.0.1 可访问  200 · 知识 72 条
  PASS  局域网 192.168.155.21 可访问  200 · 知识 72 条
② 健康检查脚本（Dockerfile HEALTHCHECK 用的那个）
  PASS  healthcheck.py 退出码 0
③ 控制台与接口
  PASS  控制台首页 / 接口文档 / 看板健康
全部通过 ✅ —— 容器里的启动方式在宿主机上等价可用
```

容器里最容易翻车的三件事（只监听 127.0.0.1、健康检查脚本路径错、时区/编码）都验过了；
剩下只有"基础镜像拉取"这一步本机无法模拟。

### B.7 局域网访问（手机看学生端）

服务以 `--host 0.0.0.0` 启动后，同一 WiFi 下手机可直接访问：

```
http://192.168.155.21:8000/          控制台
http://192.168.155.21:8000/student.html?k=xxx   学生端
```

拿不到？按顺序查：

1. `ipconfig` 看本机 IPv4 是不是 192.168.x.x
2. Windows 防火墙：首次启动时弹出的「允许访问」要勾**专用网络**；
   漏了就在「高级安全 Windows Defender 防火墙 → 入站规则」里放行 8000
3. 手机和电脑必须同一个 WiFi（有些路由器开了「AP 隔离」，设备之间不通）
4. 公司网络常禁设备互访，换手机热点试

## C. Linux 服务器（正式上线）

假设 Ubuntu 22.04，代码在 `/opt/study-abroad-agent`。

### C.1 准备

```bash
sudo apt update && sudo apt install -y python3.12 python3.12-venv nginx
cd /opt/study-abroad-agent
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/ingest_seed.py
cp .env.example .env
# 生成随机密钥并写进 .env
python3 -c "import secrets;print('AUTH_SECRET='+secrets.token_urlsafe(32))" >> .env
```

### C.2 systemd 服务

`/etc/systemd/system/study-agent.service`：

```ini
[Unit]
Description=Study-Abroad Agent
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/study-abroad-agent
Environment="PYTHONIOENCODING=utf-8"
Environment="AUTH_ENABLED=1"
ExecStart=/opt/study-abroad-agent/.venv/bin/uvicorn ai_agent_core.main:app \
          --host 127.0.0.1 --port 8000 --workers 2
Restart=always
RestartSec=3
StandardOutput=append:/var/log/study-agent.log
StandardError=append:/var/log/study-agent.err

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now study-agent
sudo systemctl status study-agent
curl -s localhost:8000/health
```

> `--host 127.0.0.1` 是故意的：对外只经 nginx，不把 8000 直接暴露。

### C.3 nginx 反代 + HTTPS

`/etc/nginx/sites-available/study-agent`：

```nginx
server {
    listen 80;
    server_name agent.example.com;

    client_max_body_size 12m;          # 学生端上传限制 10MB，留余量
    proxy_read_timeout 120s;           # AI 链路偶尔慢

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/study-agent /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d agent.example.com      # 自动配 HTTPS 并续期
```

### C.4 数据库

单机用 SQLite 足够（几十个顾问 / 几千客户）。并发上千再换 PostgreSQL：
把 `storage.py` 的四张表迁过去即可，接口层不用改。

**备份**（建议每天）：

```bash
sqlite3 /opt/study-abroad-agent/runtime/crm.db ".backup '/backup/crm-$(date +%F).db'"
tar czf /backup/rag-$(date +%F).tgz -C /opt/study-abroad-agent/runtime rag uploads
```

## 上线前检查清单

- [ ] `AUTH_SECRET` 已换成随机 32 字节（**用默认值等于没鉴权**）
- [ ] `AUTH_ENABLED=1`
- [ ] `admin` 默认密码已改，或删掉默认账号
- [ ] 对外只开 80/443，8000 只监听 127.0.0.1 或容器内
- [ ] HTTPS 已配（学生端链接是 bearer key，明文 HTTP 等于把客户材料公开）
- [ ] `runtime/` 已纳入备份，且验证过能恢复
- [ ] `.env` 不在 Git 里（`.gitignore` 已排除）
- [ ] 日志轮转已配（容器用 `json-file` 10MB×3；systemd 用 logrotate）
- [ ] 知识库数据是**当年**的（院校截止、签证资金标准）

## 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `docker: command not found` | 没装 / 没开 Docker Desktop | 装完重启，等 `Engine running` |
| 容器 `unhealthy` | 知识库为空 / 端口不对 | `docker compose logs agent` 看是否 `ingest_seed.py` 失败 |
| `port is already allocated` | 8000 被占 | `.env` 里设 `APP_PORT=8010`，重跑 compose |
| 页面能开但接口 401 | 没登录或 token 过期 | 重新登录；脚本用 `api_smoke.py` |
| 容器里中文乱码 | 少了 `PYTHONIOENCODING` | 镜像已设；自建镜像记得加 |
| 上传 413 | nginx `client_max_body_size` 太小 | 调到 12m |
| 时间显示差 8 小时 | 容器 TZ | 镜像已设 `TZ=Asia/Shanghai` |
| 数据没了 | 挂载路径写错 | `docker compose config` 看 volumes 是否指向 `./runtime` |
